7. Accessibility and Theming

Ownership visualization must be usable by all developers, including those who rely on screen readers, keyboard navigation, or high-contrast themes. The extension implements accessibility features at every layer: ARIA attributes on graph nodes, a textual graph description for screen readers, keyboard navigation within the panel, and full adaptation to VS Code's light, dark, and high-contrast themes. These features ensure that the ownership information is accessible regardless of how the developer interacts with the editor.

7.1 ARIA Labels and Screen Reader Support

Every node in the force-directed graph has three accessibility attributes: role="button" (indicating it is interactive), tabindex="0" (making it focusable via Tab key), and aria-label (providing a textual description of the variable). The aria-label includes the variable name, type, and ownership category, e.g., "Variable data, type Vec<i32>, category Owned". When a screen reader user tabs to a node, they hear this description read aloud.

Pressing Enter on a focused node triggers the same navigation action as clicking: the editor jumps to the variable's declaration line. This ensures that keyboard-only users have full access to the graph's navigation functionality without needing a mouse.

Beyond individual nodes, the panel includes a hidden aria-live region that contains a complete textual description of the entire graph. This description is generated when the graph data loads and includes: the function name, total counts (variables, borrows, moves), a list of all variables with their categories, and a list of all borrow relationships. Screen reader users can navigate to this region to get a full overview of the ownership structure without interacting with individual nodes. 

// ARIA attributes on graph nodes
node.attr('role', 'button')
    .attr('tabindex', '0')
    .attr('aria-label', d =>
      `Variable ${d.name}, type ${d.type}, category ${d.category}`)
    .on('keydown', (event, d) => {
      if (event.key === 'Enter' && vscodeApi && d.line > 0)
        vscodeApi.postMessage({ type: 'nodeClicked', line: d.line });
    });

// Graph description for screen readers (aria-live region)
(function() {
  var desc = 'Ownership graph for function ' + rawGraph.function_name + '. ';
  desc += vars.length + ' variables, ' + borrows.length + ' borrows, ' + moves.length + ' moves. ';
  vars.forEach(function(v) {
    desc += v.name + ' is ' + v.ownership_category + ' ' + v.type_display + '. ';
  });
  borrows.forEach(function(b) {
    desc += b.borrower + ' borrows ' + b.owner + ' (' + b.kind + '). ';
  });
  document.getElementById('graph-description').textContent = desc;
})();

7.2 Theme Integration

The WebView panel adapts to VS Code's active theme using CSS variables. All colors reference VS Code's theme tokens (var(--vscode-editor-background), var(--vscode-editor-foreground), var(--vscode-panel-border), etc.) rather than hardcoded values. This means the panel automatically looks correct in light themes, dark themes, and custom themes without any special handling.

The extension also contributes 10 custom theme colors to VS Code's color registry, allowing theme authors to customize ownership visualization colors. These are: borrowscope.sharedBorrow, borrowscope.mutableBorrow, borrowscope.move, borrowscope.rcArc, borrowscope.owned, borrowscope.drop, borrowscope.conflict, borrowscope.closure, borrowscope.copy, and borrowscope.rawPointer. Theme extensions can override these to match their color palette.

For high-contrast themes, the panel applies additional CSS rules: thicker borders on nodes (3px instead of 2px), thicker edge strokes (3px instead of 1.5px), thicker view toggle button borders (2px), and increased tooltip border width. These adjustments ensure that graph elements remain distinguishable when color contrast is the primary visual differentiator. The extension detects high-contrast mode via the vscode-high-contrast body class that VS Code applies automatically. 

/* Theme-adaptive CSS in the WebView panel */
body {
  font-family: var(--vscode-font-family);
  background: var(--vscode-editor-background);
  color: var(--vscode-editor-foreground);
}
#tooltip {
  background: var(--vscode-editorHoverWidget-background, #1e1e1e);
  border: 1px solid var(--vscode-editorHoverWidget-border, #454545);
}

/* High contrast mode adaptations */
.vscode-high-contrast .node circle { stroke-width: 3px; }
.vscode-high-contrast .edge path { stroke-width: 3px; }
.vscode-high-contrast #view-toggle .view-btn { border-width: 2px; }
.vscode-high-contrast #tooltip { border-width: 2px; }

/* Light theme adaptations */
.vscode-light .node circle { opacity: 0.85; }
.vscode-light .edge path { opacity: 0.7; }

7.3 Keyboard Shortcuts (6)

The extension registers 6 keyboard shortcuts for the most common operations, allowing power users to access ownership information without touching the mouse. All shortcuts use the Ctrl+Shift modifier to avoid conflicts with VS Code's built-in bindings and other extensions. The shortcuts are active only when a Rust file is focused (when: editorLangId == rust).

Shortcut Command Action
Ctrl+Shift+B borrowscope.toggleDecorations Toggle all inline decorations on/off
Ctrl+Shift+G borrowscope.focusGraph Focus the graph panel (or show message if not open)
Ctrl+Shift+N borrowscope.nextConflict Jump to next borrow conflict in the file
Ctrl+Shift+P borrowscope.prevConflict Jump to previous borrow conflict
Ctrl+Shift+T borrowscope.showTimeline Open the panel and switch to Timeline view
Ctrl+Shift+M borrowscope.showMoves Open the panel and switch to Moves view

Beyond these global shortcuts, the WebView panel supports keyboard navigation within its content. Tab cycles through graph nodes (via tabindex="0"), Enter activates the focused node (navigates to source), and the view toggle buttons are accessible via standard button focus. The landing page icons are also keyboard-accessible, allowing the developer to select a view without a mouse click.
