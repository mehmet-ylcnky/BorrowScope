5. Incremental Updates

5.1 Mutation Operations

After construction, the graph supports targeted modifications. These operations maintain all internal indices (adjacency lists, name index) consistently, ensuring that queries remain correct after mutations. 

impl OwnershipGraph {
    /// Remove a node and all its connected edges.
    pub fn remove_node(&mut self, id: NodeId);

    /// Remove a single edge, updating adjacency lists.
    pub fn remove_edge(&mut self, id: EdgeId);

    /// Mark a node as dropped at the given timestamp.
    pub fn mark_dropped(&mut self, id: NodeId, timestamp: u64);

    /// End an edge at the given timestamp.
    pub fn end_edge(&mut self, id: EdgeId, timestamp: u64);
}

remove_node is a cascading operation: it removes the node itself and all edges where the node appears as either source or target. This prevents dangling edge references, which would cause the graph to fail validation.

5.2 Graph Merging

The merge() operation combines two graphs into one, remapping all NodeIds and EdgeIds to avoid collisions. This is useful for combining graphs from multiple instrumented functions into a single program-wide ownership graph. 

/// Merge another graph into this one. Returns ID mapping.
pub fn merge(&mut self, other: &OwnershipGraph) -> HashMap<NodeId, NodeId>;

// Usage: combine graphs from two functions
let mut program_graph = OwnershipGraph::from_events(&fn_a_events);
let fn_b_graph = OwnershipGraph::from_events(&fn_b_events);
let id_map = program_graph.merge(&fn_b_graph);
// id_map maps old NodeIds from fn_b_graph to new NodeIds in program_graph

The merge operation preserves all edges from the source graph, remapping their source and target NodeIds to the new IDs assigned in the destination graph. Edge timestamps and metadata are preserved unchanged.

5.3 Index Rebuilding

After deserialization (loading a graph from JSON or MessagePack), the internal indices (adjacency lists, name index) must be rebuilt since they are not serialized. The rebuild_indices() method reconstructs all indices from the node and edge vectors: 

pub fn rebuild_indices(&mut self) {
    self.outgoing.clear();
    self.incoming.clear();
    self.name_index.clear();

    for node in &self.nodes {
        self.name_index.entry(node.name().to_string())
            .or_default().push(node.id());
    }
    for edge in &self.edges {
        self.outgoing.entry(edge.source).or_default().push(edge.id);
        self.incoming.entry(edge.target).or_default().push(edge.id);
    }
}

This is an O(n + m) operation that runs once after import. The indices are marked #[serde(skip)] to avoid serializing redundant data.
