1. Introduction

1.1 The Flat Event Stream Problem

The BorrowScope system instruments Rust programs to emit ownership events at runtime. Each event records a single operation: a variable is created, a borrow begins, a value moves, a reference count increments, a lock is acquired. The result is a chronological log that faithfully captures every ownership operation in the program's execution.

However, a flat event stream is difficult to reason about. Consider a program that creates 50 variables, borrows 30 of them, moves 10, and clones 5 Rc pointers. The event stream contains 95+ entries in temporal order. To answer "which variables borrow from data?", you must scan the entire stream, correlate borrow events with their targets, and track which borrows are still active. To answer "what is the ownership chain from a to d?", you must reconstruct move relationships across potentially hundreds of events.

These are graph queries. The natural representation of ownership relationships is a directed graph where nodes are variables and edges are ownership operations. Once constructed, the graph enables O(1) adjacency queries, standard graph algorithms (DFS, BFS, shortest path), and structural analysis (connected components, cycles, topological ordering).

1.2 Requirements for an Ownership Graph

An ownership graph for Rust must model several distinct relationship types. Unlike a simple call graph or dependency graph, ownership relationships are:

  • Typed: A shared borrow (&T) has different semantics than a mutable borrow (&mut T), which differs from a move, which differs from an Rc clone. The graph must distinguish all of these.
  • Temporal: Borrows have lifetimes. An edge that represents a borrow is only active during a specific time window. The graph must support temporal queries ("what borrows are active at timestamp 42?").
  • Hierarchical: Variables exist within scopes (functions, blocks, loops). The graph should represent containment relationships for scope-aware analysis.
  • Incremental: In a streaming scenario, events arrive one at a time. The graph must support efficient incremental construction without rebuilding from scratch.

1.3 Contributions

This paper presents the design and implementation of borrowscope-graph, a Rust crate that addresses these requirements:

  • A type system of 2 node kinds and 11 edge kinds that covers all ownership relationships in Rust, from basic borrows to concurrency primitives.
  • A single-pass O(n) construction algorithm that maps 88 runtime event types to graph operations, with active borrow tracking for correct edge termination.
  • Two construction modes: batch (from_events) for post-hoc analysis and streaming (GraphStream) with callbacks for real-time visualization.
  • Incremental update operations (add, remove, merge) that maintain index consistency.
  • Integration with borrowscope-runtime via from_runtime() for one-line graph construction.

The implementation is validated with 259 tests (including property-based tests) and benchmarked with Criterion on graphs up to 100,000 events.
