4. Streaming Construction

4.1 The GraphStream Builder

Batch construction via from_events() requires all events to be available upfront. For real-time visualization scenarios where events arrive one at a time during program execution, the GraphStream builder processes events incrementally and notifies listeners of each graph change. 

pub struct GraphStream {
    graph: OwnershipGraph,
    var_ids: HashMap<String, NodeId>,
    active_borrows: HashMap<String, Vec<EdgeId>>,
    callbacks: Vec<Box<dyn Fn(&GraphUpdate)>>,
}

impl GraphStream {
    pub fn new() -> Self;
    pub fn push(&mut self, event: &Event) -> GraphUpdate;
    pub fn push_all(&mut self, events: &[Event]) -> Vec<GraphUpdate>;
    pub fn drain_runtime(&mut self) -> Vec<GraphUpdate>;
    pub fn on_update(&mut self, callback: impl Fn(&GraphUpdate) + 'static);
    pub fn graph(&self) -> &OwnershipGraph;
    pub fn into_graph(self) -> OwnershipGraph;
}

4.2 Update Notifications

Each call to push() returns a GraphUpdate describing what changed. Registered callbacks receive the same update, enabling reactive UI patterns where the visualization updates as events arrive. 

pub enum GraphUpdate {
    NodeAdded(NodeId),
    EdgeAdded(EdgeId),
    NodeDropped(NodeId),
    EdgeEnded(EdgeId),
    NoOp,
}

The NoOp variant is returned for events that do not produce graph changes (e.g., loop iterations, binary operations). This allows consumers to distinguish meaningful updates from no-ops without inspecting the graph state.

4.3 Equivalence Guarantee

A critical property of the streaming builder: processing events one at a time via push() produces the exact same graph as processing them all at once via from_events(). This is verified by a dedicated test that constructs the same graph both ways and asserts structural equality: 

let batch_graph = OwnershipGraph::from_events(&events);

let mut stream = GraphStream::new();
stream.push_all(&events);
let stream_graph = stream.into_graph();

assert_eq!(batch_graph.node_count(), stream_graph.node_count());
assert_eq!(batch_graph.edge_count(), stream_graph.edge_count());

This guarantee means that analysis results (conflict detection, traversal, statistics) are identical regardless of which construction mode was used. Users can choose based on their latency requirements without affecting correctness.

4.4 Drain from Runtime

The drain_runtime() method bridges the streaming builder with the global event buffer. It calls borrowscope_runtime::get_events(), processes all buffered events, and returns the list of updates. This is useful for periodic polling scenarios where a visualization tool checks for new events at regular intervals: 

// Periodic polling pattern
let mut stream = GraphStream::new();
stream.on_update(|update| {
    // Send update to visualization frontend
    send_to_ui(update);
});

loop {
    stream.drain_runtime();
    std::thread::sleep(Duration::from_millis(100));
}
