6. Runtime Integration

6.1 One-Line Graph Construction

The primary integration point is OwnershipGraph::from_runtime(), which reads the global event buffer from borrowscope-runtime and constructs the graph in a single call. This is the recommended entry point for most users because it encapsulates the entire pipeline: reading events, mapping them to graph elements, tracking active borrows, and terminating edges on drop. The user does not need to understand the construction algorithm or manage any intermediate state. 

use borrowscope_runtime::*;
use borrowscope_graph::OwnershipGraph;

fn main() {
    reset();
    my_instrumented_function();

    // One line to get the complete ownership graph
    let graph = OwnershipGraph::from_runtime();

    println!("Nodes: {}, Edges: {}", graph.node_count(), graph.edge_count());
}

The graph is constructed after the instrumented code has finished executing, so there is zero overhead during the program's actual execution. The runtime captures events into a global buffer (a Vec<Event> behind a parking_lot::Mutex), and from_runtime() reads that buffer once construction is requested. This separation means that the instrumented program runs at full speed, and the graph construction cost is paid only when the user explicitly asks for it.

Calling from_runtime() multiple times is safe but produces independent graphs. Each call reads the current state of the event buffer, so if the program continues executing between calls, subsequent graphs will contain more events. Calling reset() before the instrumented function clears the buffer, ensuring that the graph contains only events from the current execution.

6.2 Filtered Construction

For large programs where only a subset of variables is of interest, filtered construction avoids building graph nodes for irrelevant events. This is particularly useful when debugging a specific ownership issue: you know which variable is problematic, and you want a focused graph centered on that variable and its relationships. 

// Only events for a specific variable
let graph = OwnershipGraph::from_runtime_for_var("data");

// Custom filter: only New and Borrow events
let graph = OwnershipGraph::from_runtime_filtered(|e| {
    matches!(e, Event::New { .. } | Event::Borrow { .. })
});

from_runtime_for_var() filters events by variable name, including borrows where the variable is the owner and moves where the variable is the source. This produces a focused subgraph centered on a single variable and its immediate relationships. For a program with 500 events, filtering to a single variable typically reduces the graph to 5-20 nodes, making it easy to visualize and reason about.

from_runtime_filtered() accepts an arbitrary predicate, enabling more complex filtering strategies. You can filter by event type (only borrows), by timestamp range (only events between t=100 and t=200), or by any combination of criteria. The predicate receives a reference to each Event and returns true to include it in the graph or false to skip it.

6.3 Dependency Architecture

The crate dependency flows in one direction: borrowscope-graph depends on borrowscope-runtime (for the Event type and get_events() function). There is no reverse dependency. This unidirectional flow is a deliberate architectural choice that keeps the runtime lightweight: projects that only need event tracking can use borrowscope-runtime alone without pulling in the graph algorithms, serialization formats, or analysis modules. 

# Cargo.toml for a project using both
[dependencies]
borrowscope-macro = "0.2"
borrowscope-runtime = { version = "0.1", features = ["track"] }
borrowscope-graph = "0.1"   # optional: add only if you need graph analysis

The track feature on borrowscope-runtime enables actual event recording. Without it, all track_* functions compile to no-ops that simply return their input, adding zero overhead to production builds. The graph crate always depends on the runtime with track enabled, since it needs the Event type and get_events() to function.

This architecture means that adding graph analysis to an existing BorrowScope-instrumented project requires only one line in Cargo.toml and one line in the source code (OwnershipGraph::from_runtime()). No changes to the instrumented functions are needed, no recompilation of the macro is required, and the runtime's behavior is unchanged.

6.4 End-to-End Workflow

The complete workflow from instrumentation to graph visualization involves three crates working together. The macro instruments the source code at compile time, the runtime captures events during execution, and the graph crate transforms those events into a queryable structure after execution completes. 

use borrowscope_macro::trace_borrow;
use borrowscope_runtime::*;
use borrowscope_graph::{OwnershipGraph, export};

#[trace_borrow]
fn process_data() {
    let data = vec![1, 2, 3];
    let r = &data;
    println!("{:?}", r);
}

fn main() {
    reset();
    process_data();

    let graph = OwnershipGraph::from_runtime();

    // Export to Graphviz DOT for visualization
    let dot = export::to_dot(&graph, &export::DotOptions::default());
    std::fs::write("ownership.dot", dot).unwrap();

    // Export to D3.js for web visualization
    let d3 = export::to_d3_json(&graph).unwrap();
    std::fs::write("ownership.json", d3).unwrap();

    // Run analysis
    let stats = borrowscope_graph::stats::statistics(&graph);
    println!("Borrows: {}, Moves: {}", stats.shared_borrows, stats.moves);
}

The output files can be consumed by external tools. The DOT file renders with Graphviz (dot -Tsvg ownership.dot -o ownership.svg) to produce a publication-quality diagram. The D3.js JSON file can be loaded directly into a web-based force-directed graph visualization. Both formats are generated in under 1ms for typical program sizes.

This workflow requires no special build configuration beyond the three crate dependencies. The analyzer must have been run previously (to generate .borrowscope/type-info.json for the macro), but the graph crate itself has no dependency on the analyzer. It works purely from the runtime event stream.
