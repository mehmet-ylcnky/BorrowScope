1. Introduction

The BorrowScope Runtime whitepaper establishes the foundation for runtime ownership tracking in Rust. It defines an event taxonomy covering 88 event types across 15 categories, implements a thread-safe global tracker, and provides algorithms for constructing ownership graphs from event streams. The runtime answers the question: how do we capture and analyze ownership operations?

This paper addresses the complementary question: how do we instrument code to emit those events?

The Instrumentation Gap

The runtime provides tracking functions like track_borrow(), track_move(), and track_drop(). But calling these functions manually throughout a codebase is impractical. A single function might require dozens of tracking calls, and maintaining them as code evolves is unsustainable.

Consider instrumenting a simple function manually: 

fn process(data: Vec<i32>) -> i32 {
    let first = &data[0];
    let result = *first * 2;
    result
}

// Manual instrumentation required:
fn process_instrumented(data: Vec<i32>) -> i32 {
    track_ownership("data", OwnershipKind::Owned);
    let first = {
        let _ref = &data[0];
        track_borrow("first", "data", BorrowKind::Immutable);
        _ref
    };
    let result = {
        let _val = *first * 2;
        track_copy("result", "first");
        _val
    };
    track_drop("first");
    track_drop("data");
    result
}

This manual approach has obvious problems:

  • Tedious: Every variable, borrow, and scope requires explicit tracking
  • Error-prone: Missing or misplaced calls produce incorrect traces
  • Unmaintainable: Code changes require updating instrumentation
  • Invasive: Tracking code obscures the actual logic

The Solution: Automatic Instrumentation

borrowscope-macro provides the #[trace_borrow] attribute that automatically transforms functions to include tracking calls. Developers annotate functions they want to trace; the macro handles the rest. 

#[trace_borrow]
fn process(data: Vec<i32>) -> i32 {
    let first = &data[0];
    let result = *first * 2;
    result
}
// Macro automatically generates all tracking calls!

The macro bridges the gap between the runtime's tracking capabilities and practical usability, making ownership visualization accessible for real-world code.
