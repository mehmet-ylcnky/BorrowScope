1. Introduction

The borrowscope-runtime whitepaper establishes the foundation for runtime ownership tracking in Rust. It defines an event taxonomy covering 88 event types across 15 categories, implements a thread-safe global tracker, and provides algorithms for constructing ownership graphs from event streams. The runtime answers the question: how do we capture and analyze ownership operations?

This paper addresses the complementary question: how do we instrument code to emit those events?

The Instrumentation Gap

The runtime provides tracking functions like track_borrow(), track_move(), and track_drop(). But calling these functions manually throughout a codebase is impractical. A single function might require dozens of tracking calls, and maintaining them as code evolves is unsustainable.

Consider instrumenting a simple function manually. Even a three-line function requires tracking: the parameter takes ownership, indexing creates a borrow, dereferencing copies the value, and both variables must be dropped at scope exit. The instrumented version below shows the tracking calls that would be needed: 

fn process(data: Vec<i32>) -> i32 {
    let first = &data[0];
    let result = *first * 2;
    result
}

// Manual instrumentation required:
fn process_instrumented(data: Vec<i32>) -> i32 {
    track_ownership("data", OwnershipKind::Owned);
    let first = {
        let _ref = &data[0];
        track_borrow("first", "data", BorrowKind::Immutable);
        _ref
    };
    let result = {
        let _val = *first * 2;
        track_copy("result", "first");
        _val
    };
    track_drop("first");
    track_drop("data");
    result
}

This manual approach quickly becomes impractical. The process is tedious—every variable binding, borrow expression, and scope boundary requires an explicit tracking call. It's also error-prone: a single missing or misplaced call produces incorrect traces that misrepresent the actual ownership flow. Worse, the instrumentation is unmaintainable—any code change requires carefully updating the corresponding tracking calls, and forgetting to do so silently corrupts the output. Finally, the approach is invasive: the tracking code overwhelms the actual logic, making the instrumented function nearly unreadable.

The Solution: Automatic Instrumentation

borrowscope-macro provides the #[trace_borrow] attribute that automatically transforms functions to include tracking calls. Developers annotate functions they want to trace; the macro handles the rest. 

#[trace_borrow]
fn process(data: Vec<i32>) -> i32 {
    let first = &data[0];
    let result = *first * 2;
    result
}

With a single attribute, the macro analyzes the function body at compile time, identifies all ownership-relevant operations, and injects the appropriate tracking calls automatically. The original code remains clean and readable while the generated instrumentation captures every variable binding, borrow, copy, and drop. This bridges the gap between the runtime's powerful tracking capabilities and practical usability—developers simply annotate functions they want to trace, and the macro handles the rest, making ownership visualization accessible for real-world codebases without sacrificing code clarity.
