6. Integration with Runtime

The macro and runtime form a complete system. Understanding their relationship clarifies how ownership tracking works end-to-end. 

┌─────────────────────────────────────────────────────────────────┐
│                        Your Code                                │
│  #[trace_borrow]                                                │
│  fn process(data: Vec<i32>) { ... }                            │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼ compile-time transformation
┌─────────────────────────────────────────────────────────────────┐
│                    borrowscope-macro                            │
│  • Parses function AST                                          │
│  • Identifies ownership operations                              │
│  • Generates tracking calls                                     │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼ generated code calls
┌─────────────────────────────────────────────────────────────────┐
│                   borrowscope-runtime                           │
│  • Receives tracking calls at runtime                           │
│  • Stores events in thread-safe buffer                          │
│  • Builds ownership graphs                                      │
│  • Provides query/export APIs                                   │
└─────────────────────────────────────────────────────────────────┘

Event Flow

  1. Compile time: Macro transforms annotated functions
  2. Runtime: Transformed code emits events via runtime API
  3. Analysis: Runtime builds graphs from event stream
  4. Output: Graphs exported for visualization

Zero-Cost When Disabled

Both crates support conditional compilation. When the tracking feature is disabled, all tracking calls compile to no-ops, achieving true zero-cost abstraction as described in the runtime whitepaper.
