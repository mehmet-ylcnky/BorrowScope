3. How It Works

3.1 The #[trace_borrow] Attribute

The #[trace_borrow] attribute is an attribute procedural macro that transforms function definitions at compile time. When the Rust compiler encounters this attribute, it invokes the macro with the function's token stream before any type checking occurs. The macro then performs a four-stage transformation: it parses the raw tokens into a structured Abstract Syntax Tree (AST) using the syn crate, walks the function body to identify ownership-relevant operations like variable bindings and borrow expressions, generates tracking calls for each identified operation, and finally emits the transformed function as new tokens using the quote crate. 

// The transformation pipeline

┌──────────────────────────────────────────────────────────────────────────────┐
│  #[trace_borrow]                                                          │
│  fn example(x: String) { let y = &x; }                                    │
└──────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼  1. Parse with syn
┌──────────────────────────────────────────────────────────────────────────────┐
│  ItemFn {                                                                    │
│    ident: "example",                                                         │
│    inputs: [FnArg { ident: "x", ty: "String" }],                             │
│    body: Block {                                                             │
│      stmts: [                                                                │
│        Local {                                                               │
│          pat: Ident("y"),                                                    │
│          init: Expr::Reference { mutability: None, expr: Path("x") }         │
│        }                                                                     │
│      ]                                                                       │
│    }                                                                         │
│  }                                                                           │
└──────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼  2. Walk AST & identify operations
┌──────────────────────────────────────────────────────────────────────────────┐
│  Operations detected:                                                        │
│    • Parameter "x" takes ownership of String                                 │
│    • Variable "y" borrows from "x" (immutable)                               │
│    • Scope exit: drop "y", then drop "x"                                     │
└──────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼  3. Generate tracking calls
┌──────────────────────────────────────────────────────────────────────────────┐
│  fn example(x: String) {                                                    │
│    borrowscope_runtime::track_scope_enter("example");                        │
│    borrowscope_runtime::track_ownership("x", "String", 1);                   │
│    let y = {                                                                │
│      let __tmp = &x;                                                        │
│      borrowscope_runtime::track_borrow("y", 2, "x", 1, Immutable);           │
│      __tmp                                                                   │
│    };                                                                        │
│    borrowscope_runtime::track_drop("y", 2);                                  │
│    borrowscope_runtime::track_drop("x", 1);                                  │
│    borrowscope_runtime::track_scope_exit("example");                         │
│  }                                                                           │
└──────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼  4. Emit as TokenStream
┌──────────────────────────────────────────────────────────────────────────────┐
│  Compiler receives transformed tokens, continues with type checking...       │
└──────────────────────────────────────────────────────────────────────────────┘

The AST produced by syn provides structured access to every syntactic element: function signatures with their parameters and return types, block statements containing local variable declarations, and expressions including references, method calls, and control flow. This structure allows the macro to traverse the function systematically, matching patterns like Expr::Reference for borrow expressions or Local for variable bindings, without resorting to fragile string manipulation. 

// Input to macro
#[trace_borrow]
fn example(x: String) {
    let y = &x;
    println!("{}", y);
}

// Output from macro (conceptual)
fn example(x: String) {
    borrowscope_runtime::track_scope_enter("example");
    borrowscope_runtime::track_ownership("x", "String");
    let y = {
        let __tmp = &x;
        borrowscope_runtime::track_borrow("y", "x", BorrowKind::Immutable);
        __tmp
    };
    println!("{}", y);
    borrowscope_runtime::track_drop("y");
    borrowscope_runtime::track_drop("x");
    borrowscope_runtime::track_scope_exit("example");
}

3.2 Transformation Pipeline

TokenStream ──▶ syn::parse ──▶ ItemFn AST ──▶ Analyze Body ──▶ Generate Calls ──▶ quote! output

Stage 1: Parsing

The macro receives a TokenStream—Rust's representation of source code as a sequence of tokens (identifiers, punctuation, literals, and delimiters). This raw stream contains no structural information; it's essentially the lexer's output. The syn crate transforms this flat sequence into a rich, typed Abstract Syntax Tree. For a function, this produces an ItemFn structure containing the function's visibility, name, generics, parameter list with types, return type, and most importantly, the function body as a Block of statements. Each statement is further decomposed: local bindings become Local nodes with patterns and initializers, expressions are categorized by kind (reference, method call, binary operation, etc.), and control flow structures expose their conditions and branches. This structured representation enables precise, type-safe traversal of the code.

Stage 2: Analysis

With the AST in hand, the macro performs a depth-first traversal of the function body using a custom OwnershipVisitor. This visitor maintains state as it walks: a mapping of variable names to unique tracking IDs, a scope stack for tracking which variables need to be dropped at each scope exit, and sets identifying special variable types (smart pointers, channels, lock guards). At each AST node, the visitor pattern-matches to identify ownership-relevant operations. A Local node with an initializer indicates a new variable binding—the visitor records it and assigns a tracking ID. An Expr::Reference signals a borrow, with the mutability field distinguishing shared from exclusive borrows. Method calls are inspected for ownership-transferring patterns like .clone(), .lock(), or .into(). Block boundaries trigger scope tracking, and the visitor maintains a stack to ensure drops are emitted in reverse declaration order when scopes exit.

Stage 3: Code Generation

For each identified operation, the macro constructs tracking calls using the quote! macro, which provides a template syntax for generating Rust code. Variable names and IDs are interpolated into these templates to produce calls like track_borrow("y", 2, "x", 1, BorrowKind::Immutable). The generated calls must be inserted at precise locations: ownership tracking immediately after a binding, borrow tracking wrapped around the reference expression (using a temporary to preserve evaluation order), and drop tracking at scope boundaries in reverse declaration order. The quote! output is a new TokenStream that the compiler receives in place of the original function, continuing compilation with the instrumented version as if the developer had written it by hand.

3.3 Code Generation

The quote! macro provides a powerful templating system for generating Rust code. Within the template, the # prefix interpolates values from the macro's context—variable names, types, and computed IDs become part of the generated code. The stringify! macro converts identifiers to string literals at compile time, allowing variable names to be passed to tracking functions without runtime overhead. Below is a simplified example showing how a variable binding generates its tracking call: 

// Inside the procedural macro
let var_name = &local.pat;
let var_id = self.next_var_id();
let tracking_call = quote! {
    borrowscope_runtime::track_ownership(
        stringify!(#var_name), 
        #var_id,
        OwnershipKind::Owned
    );
};

The actual implementation is more sophisticated, handling pattern destructuring (where a single let may bind multiple variables), conditional tracking based on configuration flags, and careful placement to preserve the original code's semantics. For borrow expressions, the macro wraps the reference in a block that captures the value in a temporary, emits the tracking call, and then yields the temporary—ensuring the tracking happens at exactly the right moment without changing evaluation order or introducing additional borrows that could conflict with the original code's borrow checker constraints.
