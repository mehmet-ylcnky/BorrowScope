4. Ownership Graph Construction

The ownership graph construction algorithm transforms temporal event streams into structured relationship graphs that represent the complete ownership topology of a program execution. This transformation is critical for visualization, analysis, and understanding of ownership patterns. The algorithm operates in linear time O(n) where n is the number of events, making it suitable for real-time analysis of large-scale applications.

4.1 Graph Model and Data Structures

The ownership graph model represents variables as nodes and ownership relationships as directed edges. Each node contains complete metadata about a variable's lifecycle, while edges capture the temporal and semantic aspects of ownership relationships. The model supports three fundamental relationship types: ownership, immutable borrowing, and mutable borrowing, each with distinct temporal characteristics.

Core Data Structures

The ownership graph model relies on three fundamental data structures that capture the complete state of variable lifecycles and their relationships. The Variable struct represents individual tracked variables with temporal metadata, while the Relationship enum captures the semantic connections between variables. The OwnershipGraph struct combines these elements into a cohesive structure optimized for both construction and analysis operations.

Each variable node maintains comprehensive lifecycle information including creation and destruction timestamps, enabling precise temporal analysis. The relationship edges distinguish between permanent ownership connections and temporary borrow relationships, with immutable and mutable borrows tracked separately to reflect Rust's borrowing semantics. The graph structure includes an internal index for O(1) variable lookup operations, essential for efficient graph construction from large event streams.

#[serde(tag = "kind")]
pub enum Relationship {

        to: String,    // Owned variable ID

        end: u64,      // Borrow end timestamp

    BorrowsMut {
        from: String,  // Borrower variable ID
        to: String,    // Borrowed variable ID
        start: u64,    // Borrow creation timestamp
        end: u64,      // Borrow end timestamp
    },
}

4.2 Graph Construction Algorithm

The graph construction algorithm processes events in chronological order, maintaining active variable states and relationship mappings. The algorithm uses a two-phase approach: first building the variable lifecycle map, then constructing relationships based on temporal overlaps and event semantics. This approach ensures O(n) time complexity while handling complex ownership patterns including cycles, temporary borrows, and smart pointer relationships.

Algorithm Implementation

The graph construction algorithm transforms chronologically ordered events into structured ownership relationships through a sophisticated two-phase process. The first phase builds comprehensive variable lifecycle maps by processing creation, borrowing, and destruction events in temporal order. The second phase converts these lifecycle maps into graph nodes and edges, ensuring that all temporal relationships are preserved in the final structure.

The algorithm maintains active state tracking throughout event processing, using hash maps for efficient variable lookup and borrow correlation. Each event type triggers specific state transitions: New events initialize variable lifecycles, Borrow and BorrowMut events create temporary relationship tracking, and Drop events finalize both variable lifetimes and any associated borrow relationships. This approach ensures O(n) time complexity while handling complex scenarios like nested borrows, smart pointer operations, and concurrent access patterns. 

impl OwnershipGraph {
    /// Construct ownership graph from chronologically ordered events
    /// Time complexity: O(n) where n = number of events
    /// Space complexity: O(v + e) where v = variables, e = relationships
    pub fn from_events(events: &[Event]) -> Self {
        let mut graph = OwnershipGraph {
            nodes: Vec::new(),
            edges: Vec::new(),
            node_index: HashMap::new(),
        };

        // Phase 1: Build variable lifecycle map
        // Track creation, modification, and destruction events
        let mut variable_states = HashMap::<String, VariableState>::new();
        let mut active_borrows = HashMap::<String, BorrowInfo>::new();

        // Process events chronologically to build state transitions
        for event in events {
            match &event.event_type {
                // ═══════════════════════════════════════════════════════
                // VARIABLE CREATION: Initialize new variable state
                // ═══════════════════════════════════════════════════════
                EventType::New { name, type_name, .. } => {
                    variable_states.insert(
                        event.id.clone(),
                        VariableState {
                            name: name.clone(),
                            type_name: type_name.clone(),
                            created_at: event.timestamp,
                            dropped_at: None,
                            borrow_history: Vec::new(),
                        }
                    );
                }

                // ═══════════════════════════════════════════════════════
                // IMMUTABLE BORROW: Track shared reference creation
                // ═══════════════════════════════════════════════════════
                EventType::Borrow { name, source, .. } => {
                    // Create borrower variable if not exists
                    if !variable_states.contains_key(&event.id) {
                        variable_states.insert(
                            event.id.clone(),
                            VariableState {
                                name: name.clone(),
                                type_name: format!("&{}",
                                    variable_states.get(source)
                                        .map(|s| s.type_name.as_str())
                                        .unwrap_or("Unknown")),
                                created_at: event.timestamp,
                                dropped_at: None,
                                borrow_history: Vec::new(),
                            }
                        );
                    }

                    // Track active borrow for relationship construction
                    active_borrows.insert(
                        event.id.clone(),
                        BorrowInfo {
                            borrower: event.id.clone(),
                            borrowed: source.clone(),
                            borrow_type: BorrowType::Immutable,
                            start_time: event.timestamp,
                        }
                    );
                }

                // ═══════════════════════════════════════════════════════
                // MUTABLE BORROW: Track exclusive reference creation
                // ═══════════════════════════════════════════════════════
                EventType::BorrowMut { name, source, .. } => {
                    // Similar to immutable borrow but with exclusive semantics
                    if !variable_states.contains_key(&event.id) {
                        variable_states.insert(
                            event.id.clone(),
                            VariableState {
                                name: name.clone(),
                                type_name: format!("&mut {}",
                                    variable_states.get(source)
                                        .map(|s| s.type_name.as_str())
                                        .unwrap_or("Unknown")),
                                created_at: event.timestamp,
                                dropped_at: None,
                                borrow_history: Vec::new(),
                            }
                        );
                    }

                    active_borrows.insert(
                        event.id.clone(),
                        BorrowInfo {
                            borrower: event.id.clone(),
                            borrowed: source.clone(),
                            borrow_type: BorrowType::Mutable,
                            start_time: event.timestamp,
                        }
                    );
                }

                // ═══════════════════════════════════════════════════════
                // VARIABLE DROP: Finalize variable lifecycle
                // ═══════════════════════════════════════════════════════
                EventType::Drop { name } => {
                    // Mark variable as dropped and finalize any active borrows
                    if let Some(state) = variable_states.get_mut(&event.id) {
                        state.dropped_at = Some(event.timestamp);
                    }

                    // Finalize any borrow relationships involving this variable
                    if let Some(borrow_info) = active_borrows.remove(&event.id) {
                        graph.add_borrow_relationship(
                            borrow_info,
                            event.timestamp
                        );
                    }
                }

                // Handle other event types (Move, RcClone, etc.)
                _ => { /* Additional event type handling */ }
            }
        }

        // Phase 2: Convert variable states to graph nodes
        for (id, state) in variable_states {
            let variable = Variable {
                id: id.clone(),
                name: state.name,
                type_name: state.type_name,
                created_at: state.created_at,
                dropped_at: state.dropped_at,
                lifetime_duration: state.dropped_at
                    .map(|end| end - state.created_at),
            };

            graph.node_index.insert(id, graph.nodes.len());
            graph.nodes.push(variable);
        }

        // Finalize any remaining active borrows
        for (_, borrow_info) in active_borrows {
            // Use last event timestamp as end time for unclosed borrows
            let end_time = events.last()
                .map(|e| e.timestamp)
                .unwrap_or(borrow_info.start_time);

            graph.add_borrow_relationship(borrow_info, end_time);
        }

        graph
    }

    /// Add borrow relationship edge to the graph
    fn add_borrow_relationship(&mut self, borrow_info: BorrowInfo, end_time: u64) {
        let relationship = match borrow_info.borrow_type {
            BorrowType::Immutable => Relationship::BorrowsImmut {
                from: borrow_info.borrower,
                to: borrow_info.borrowed,
                start: borrow_info.start_time,
                end: end_time,
            },
            BorrowType::Mutable => Relationship::BorrowsMut {
                from: borrow_info.borrower,
                to: borrow_info.borrowed,
                start: borrow_info.start_time,
                end: end_time,
            },
        };

        self.edges.push(relationship);
    }
}

4.3 Complex Ownership Patterns

Real-world Rust programs exhibit complex ownership patterns that challenge simple graph models. The borrowscope-runtime graph construction algorithm handles advanced scenarios including smart pointer cycles, interior mutability, and async ownership transfers. These patterns require sophisticated temporal analysis and relationship inference to construct accurate ownership graphs.

Smart Pointer Cycles and Reference Counting

Smart pointer cycles represent one of the most challenging ownership patterns in Rust. When using Rc<RefCell<T>> for shared mutable data structures like linked lists or graphs, it's possible to create reference cycles that prevent automatic memory deallocation. The borrowscope-runtime graph construction algorithm detects these cycles by analyzing ownership relationships and identifying strongly connected components in the graph.

The following example demonstrates a classic reference cycle scenario where two nodes reference each other through Rc smart pointers. This pattern is common in data structures like doubly-linked lists, graphs, or parent-child relationships where bidirectional references are needed. The graph construction algorithm captures both the individual Rc relationships and the resulting cycle, enabling analysis tools to warn developers about potential memory leaks.

Temporal Borrow Analysis

Temporal borrow analysis examines the timing and overlap of borrow operations to identify patterns that would cause compile-time errors in Rust. This analysis is particularly valuable for understanding complex borrowing scenarios where multiple references exist simultaneously, and for educational purposes where developers need to visualize why certain borrow patterns are rejected by the compiler.

The example below demonstrates a sophisticated borrowing scenario involving multiple immutable borrows followed by an attempted mutable borrow. While Rust's borrow checker prevents this pattern at compile time, borrowscope-runtime captures the attempted operations and provides temporal analysis showing exactly when and why conflicts occur. This enables developers to understand the precise timing requirements of Rust's borrowing rules and helps identify the minimal changes needed to resolve borrow conflicts.

Graph Analysis Methods

The ownership graph provides a foundation for sophisticated analysis algorithms that can detect patterns, conflicts, and optimization opportunities in Rust programs. These analysis methods operate on the constructed graph to provide insights that would be difficult to obtain from raw event streams alone. The algorithms leverage graph theory concepts like strongly connected components, temporal overlap analysis, and path traversal to identify meaningful patterns in ownership behavior.

The implementation below showcases three critical analysis capabilities: cycle detection for identifying memory leaks in smart pointer structures, borrow conflict analysis for understanding compile-time borrowing errors, and comprehensive metrics calculation for performance and complexity assessment. Each method provides actionable insights that can guide code optimization, debugging efforts, and educational understanding of Rust's ownership system. 

impl OwnershipGraph {
    /// Detect cycles in the ownership graph
    /// Returns list of strongly connected components
    pub fn detect_cycles(&self) -> Vec<Vec<String>> {
        let mut visited = HashSet::new();
        let mut cycles = Vec::new();

        for node in &self.nodes {
            if !visited.contains(&node.id) {
                let cycle = self.dfs_cycle_detection(&node.id, &mut visited);
                if !cycle.is_empty() {
                    cycles.push(cycle);
                }
            }
        }

        cycles
    }

    /// Analyze temporal borrow conflicts
    /// Returns overlapping borrow periods that would cause compile errors
    pub fn analyze_borrow_conflicts(&self) -> Vec<BorrowConflict> {
        let mut conflicts = Vec::new();

        // Group borrows by target variable
        let mut borrows_by_target = HashMap::<String, Vec<&Relationship>>::new();

        for edge in &self.edges {
            let target = match edge {
                Relationship::BorrowsImmut { to, .. } => to,
                Relationship::BorrowsMut { to, .. } => to,
                _ => continue,
            };

            borrows_by_target
                .entry(target.clone())
                .or_default()
                .push(edge);
        }

        // Check for temporal overlaps within each target
        for (target, borrows) in borrows_by_target {
            for i in 0..borrows.len() {
                for j in (i + 1)..borrows.len() {
                    if let Some(conflict) = self.check_borrow_overlap(borrows[i], borrows[j]) {
                        conflicts.push(conflict);
                    }
                }
            }
        }

        conflicts
    }

    /// Calculate graph metrics for analysis
    pub fn calculate_metrics(&self) -> GraphMetrics {
        GraphMetrics {
            node_count: self.nodes.len(),
            edge_count: self.edges.len(),
            avg_lifetime: self.calculate_average_lifetime(),
            max_borrow_depth: self.calculate_max_borrow_depth(),
            cycle_count: self.detect_cycles().len(),
            conflict_count: self.analyze_borrow_conflicts().len(),
        }
    }
}
