Related Work and Comparative Analysis

BorrowScope joins a growing ecosystem of tools aimed at making Rust's ownership system more understandable. This section provides an objective comparison with related projects, identifying where BorrowScope excels and where it has limitations.

Comparative Analysis

Aquascope (Brown University)

Aquascope represents the most academically rigorous approach to ownership visualization, emerging from Brown University's Cognitive Engineering Lab with peer-reviewed research published at OOPSLA 2023. Its primary strength lies in visualizing how the borrow checker reasons about code at compile-time, showing permission changes (read/write/own) on variables as the program executes. This permission model provides an intuitive mental framework that has proven effective in educational contexts—Aquascope powers the visualizations in "The Rust Book Experiment" and integrates seamlessly with mdBook for creating interactive learning materials. With 2.9k GitHub stars and active development since 2022, it has established itself as a mature tool in the ecosystem.

BorrowScope takes a fundamentally different approach that complements rather than competes with Aquascope. Where Aquascope focuses on compile-time reasoning, BorrowScope captures actual runtime behavior through an event-sourced architecture. This enables temporal analysis, replay capabilities, and ownership graph construction—features impossible with static visualization alone. BorrowScope provides a programmatic Rust library API for building custom analysis tools, whereas Aquascope primarily produces visualization output. Perhaps most significantly, BorrowScope achieves true zero-cost abstraction: when tracking is disabled, all instrumentation compiles away completely. Aquascope's runtime visualization relies on Miri, which imposes prohibitive performance overhead unsuitable for production codebases. BorrowScope also works on stable Rust for basic use, while Aquascope requires a nightly toolchain.

However, BorrowScope cannot replicate Aquascope's compile-time borrow checker visualization or its explicit permission (R/W/O) model. For understanding why the borrow checker accepts or rejects code, Aquascope remains the superior choice. BorrowScope also has a smaller community and less mature ecosystem compared to Aquascope's established presence in Rust education.

Boris (Master's Thesis Project)

Boris emerged from a master's thesis at Julius-Maximilians-University Würzburg, focusing on memory layout visualization. Its distinctive contribution is showing actual memory representation—how ownership transfers and borrow scopes map to physical memory. The standalone desktop application built with egui provides an accessible entry point, and a web viewer allows exploring pre-analyzed examples without installation. For beginners trying to connect Rust's abstract ownership concepts to concrete memory behavior, Boris offers unique visual insights.

BorrowScope differs fundamentally in that it captures actual runtime execution rather than performing static analysis. Boris analyzes code structure; BorrowScope observes what actually happens when code runs. This runtime focus enables BorrowScope to handle production-scale codebases, while Boris explicitly acknowledges limitations to small examples. BorrowScope's library API enables programmatic integration into larger toolchains, whereas Boris operates as a standalone visualization tool. Development activity also differs significantly: Boris has 11 commits and appears dormant, while BorrowScope continues active development.

That said, BorrowScope cannot visualize memory layout the way Boris does. For developers who need to understand how ownership maps to actual memory representation, Boris provides capabilities BorrowScope lacks. BorrowScope also has no standalone GUI application—it requires integration into user code or tooling.

Flowistry (Will Crichton)

Flowistry, developed by Will Crichton, approaches Rust program understanding from an information flow perspective rather than ownership visualization. Published at PLDI 2022, the research demonstrates how ownership types enable sound and precise information flow analysis. The practical result is a VSCode extension that helps developers understand which code can affect other code, providing a "focus mode" that filters out irrelevant parts when debugging or comprehending complex codebases. This IDE integration makes Flowistry immediately accessible to developers in their existing workflow.

BorrowScope and Flowistry answer fundamentally different questions. Flowistry asks "what code affects this?"—useful for understanding dependencies and debugging. BorrowScope asks "what ownership operations occurred?"—useful for understanding runtime behavior and building analysis tools. Flowistry performs static analysis; BorrowScope captures actual execution. BorrowScope's comprehensive event taxonomy (88 event types) and graph construction capabilities serve different use cases than Flowistry's dependency highlighting.

The tools are genuinely complementary: use Flowistry to understand code structure and dependencies during development, use BorrowScope to observe actual ownership behavior during execution and build custom analysis tools.

REVIS (VSCode Extension)

REVIS takes a narrowly focused approach: visualizing lifetime-related Rust compiler errors. When the borrow checker rejects code, REVIS draws lifetime spans directly in the editor, helping developers understand why the error occurred and how to fix it. This immediate, in-editor feedback on save makes REVIS particularly valuable for learning lifetime concepts and debugging borrow checker errors. The research paper "REVIS: An Error Visualization Tool for Rust" (2023) documents its efficacy for student learners.

BorrowScope operates in a different domain entirely. REVIS helps fix broken code; BorrowScope helps understand working code. REVIS visualizes compile-time errors; BorrowScope tracks runtime behavior. BorrowScope's broader scope—tracking all ownership operations, not just error cases—serves different purposes than REVIS's targeted error visualization.

The distinction is clear: when code fails to compile due to lifetime errors, REVIS helps diagnose and fix the problem. When code compiles successfully and you want to understand its ownership behavior at runtime, BorrowScope provides that visibility. Both tools have their place in a Rust developer's toolkit.

BorrowScope's Unique Position

What Makes BorrowScope Different

  1. Only tool with runtime event-sourced architecture — enables temporal analysis impossible with static tools
  2. Only tool with programmatic API — others are visualization outputs or IDE plugins
  3. Only tool with zero-cost abstraction — can be used in production without overhead when disabled
  4. Comprehensive event taxonomy — 88 event types vs ad-hoc tracking in others

Complementary Usage

These tools are complementary, not competing. A comprehensive approach to understanding Rust ownership might use:

  • Aquascope — to understand how the borrow checker reasons about code
  • REVIS — to fix lifetime-related compiler errors
  • Flowistry — to understand code dependencies and information flow
  • BorrowScope — to observe actual runtime ownership behavior and build custom analysis tools
