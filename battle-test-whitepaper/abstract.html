Abstract

The companion whitepaper "Rust's Type Information Barrier" establishes the theoretical constraints preventing procedural macros from accessing type information during compilation. This paper provides empirical validation of those theoretical predictions through systematic testing of the #[trace_borrow] macro against five production-grade Rust codebases: ripgrep, tokio, bat, fd, and zoxide.

Across 14,562 functions spanning diverse domains—async runtimes, CLI tools, and system utilities—we achieve an average pass rate of 80.5%, closely aligning with the theoretical prediction of ~70-95% for heuristic-based approaches. We identify and classify six primary error patterns, with ERR-003 (mutable borrow conflicts) appearing in all five projects and ERR-012 (trait implementation signature mismatch) accounting for 54% of errors in the tokio codebase alone.

Root cause analysis reveals that each error category traces directly to manifestations of the type information barrier documented in the theoretical paper: syntactic ambiguity between trait declarations and implementations, inability to detect ownership semantics, and context-sensitivity that requires name resolution unavailable to macros.

We propose a prioritized fix strategy targeting ERR-003 and ERR-012 first, with projected improvements raising pass rates to 95-100% across all tested projects. These findings validate the phased implementation approach recommended in the theoretical paper and provide concrete guidance for BorrowScope's continued development.
