3.3 Pass Rate Analysis

The variation in pass rates across projects reveals important patterns:

High Performers (82-86%): ripgrep, bat, fd

These CLI tools share common characteristics: straightforward function signatures, limited trait complexity, and conventional ownership patterns. Their code prioritizes clarity and performance over abstraction, resulting in patterns that syntactic analysis handles well.

Lower Performers (71-79%): tokio, zoxide

Tokio's 71.2% pass rate—the lowest in our study—reflects its architectural complexity. As an async runtime, tokio makes extensive use of:

  • Trait definitions with many associated types
  • Generic implementations with complex bounds
  • Async trait methods (via async-trait or manual impl)
  • Internal macros that generate trait implementations

Notably, 54% of tokio's errors stem from a single pattern: ERR-012 (trait implementation signature mismatch). This concentration suggests that fixing one error category could dramatically improve tokio's pass rate.

Test Files: Near-Perfect Pass Rate

Across all projects, test files (*_test.rs, tests/*.rs) achieve 95-100% pass rates. Test code tends to use simpler patterns: direct function calls, concrete types, and minimal trait abstraction. This observation supports the theoretical prediction that "common patterns" are well-handled while "edge cases" require type information.

Error Concentration

A critical finding is that errors are not uniformly distributed. Across all projects:

  • Top 2 error types (ERR-003, ERR-012) account for 73% of all failures
  • Top 4 error types account for 91% of all failures
  • The remaining error types are rare edge cases

This concentration is encouraging: targeted fixes for a small number of patterns can yield disproportionate improvements in overall pass rates.
