Abstract

The BorrowScope ecosystem consists of five components that each address a different aspect of Rust ownership visualization: a static analyzer that extracts type information into type-info.json, a procedural macro that instruments code using that type information, a runtime library that records 88 event types during execution, a Language Server that provides real-time static analysis, and a VS Code extension that renders 11 interactive visualization views. Each component was developed and validated independently (documented in separate papers), but their full value emerges only when they operate as a unified pipeline. This paper presents that pipeline as an integrated system, demonstrating how data flows from source code to visual feedback through a single "Run Instrumented" button click.

The central integration point is type-info.json, a structured schema containing per-variable semantic information (ownership category, initializer kind, type flags) that the analyzer produces and the macro consumes at compile time. This schema enables the macro to make semantic instrumentation decisions (distinguishing Rc::clone from generic .clone(), Cow::Borrowed from Cow::Owned) without heuristics. The instrumented program then produces runtime events that the VS Code extension merges with the LSP's static analysis, detecting divergences where predictions and observations disagree. The new orchestration command (borrowscope.runInstrumented) automates the entire sequence: analyzer execution, compilation, program run, and merge trigger, with a status bar button showing live progress.

The pipeline maintains zero heuristics throughout all five components: the analyzer uses ra_ap_* compiler APIs for type resolution, the macro dispatches based on semantically resolved initializer_kind values, the LSP uses Salsa incremental computation for borrow scope analysis, and the extension uses structured JSON responses for visualization. Performance is bounded at each stage: analyzer 30-40s (one-time), macro expansion adds negligible compile time, runtime overhead is approximately 75ns per tracked event, LSP analysis completes within 100ms per function, and the merge processes 1000 events in under 100ms. The ecosystem is validated by over 2,100 tests across all components, with 563 macro tests, 775 runtime tests, 107 LSP protocol tests, and 721 extension tests confirming end-to-end correctness.
