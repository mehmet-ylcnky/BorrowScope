Abstract

Static ownership analysis and runtime event tracking represent two fundamentally different approaches to understanding Rust's ownership system. The borrowscope-lsp server performs static analysis using rust-analyzer's semantic engine, predicting ownership categories, borrow scopes, move destinations, and potential conflicts across all code paths simultaneously. The borrowscope-runtime library records 88 event types during actual program execution, capturing precise timestamps, real reference counts, observed drop order, and the exact sequence of ownership operations along one execution path. Each approach has blind spots that the other can fill: static analysis cannot observe Rc reference cycles or detect which branches were actually taken, while runtime observation cannot see all possible conflicts or resolve cross-function borrow paths without semantic type information.

This paper presents a merge algorithm that correlates these two data sources into a unified view. The algorithm maps runtime variable IDs (e.g., "data_0") to static variable declarations (e.g., data: Vec<i32> at line 5) using name, line, and file matching. For each correlated variable, it aggregates runtime events into a RuntimeInfo structure (actual lifetime, borrow counts, ref count peak, drop order, await crossings) and compares this observed behavior against the static prediction. When the two disagree in a meaningful way, the system classifies the disagreement into one of 9 divergence kinds: Rc leaks, reference cycles, missing drops, borrows held across await points, unsafe hidden behavior, conditional moves, weak upgrade failures, channel receive failures, and use-after-move. Each divergence carries a severity level (error, warning, or info) and an actionable suggestion telling the developer what to investigate.

The merge completes in under 100ms for typical event streams (1000 events), enabling real-time overlay in the VS Code extension. The divergence detection is validated by 64 dedicated tests covering all 9 kinds with both positive cases (divergence correctly detected) and negative cases (no false positives on correct code). The system also includes specialized async borrow tracking that detects borrows held across .await points, directly explaining the common "future is not Send" compiler error that confuses many Rust developers. Together, the merge layer gives developers the best of both worlds: instant static feedback during editing, and precise runtime validation after execution, with divergences highlighted exactly where the two perspectives disagree.
