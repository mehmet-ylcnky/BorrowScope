5. The Merge Algorithm

Once variables are mapped between the two worlds, the merge algorithm constructs a unified representation for each variable. This representation combines the static prediction (type, category, is_copy) with aggregated runtime observations (lifetime, borrow counts, ref counts, drop order) into a single MergedVariable structure. The algorithm then classifies the agreement between the two sides and runs divergence detection. This section describes each step of the merge pipeline.

5.1 MergedVariable Construction

The mergeViews() function is the entry point of the merge pipeline. It takes the static variable list (from the LSP's ownership graph), the runtime event array (from the file watcher or WebSocket), and an optional file filter. It produces a MergedVariable[] array where each entry represents one variable with both perspectives combined.

For each mapped variable (has both runtime events and a static match), the function builds a RuntimeInfo by aggregating events, runs divergence detection, and computes the agreement status. For unmapped runtime variables (no static match), it creates an entry with static_info: null and agreement "runtime_only". For unmapped static variables (no runtime events), it creates an entry with runtime_info: null and agreement "static_only". The result is a complete inventory of every variable known to either side. 

export function mergeViews(
  staticVars: StaticVariable[],
  events: RuntimeEvent[],
  file?: string
): MergedVariable[] {
  const mapped = mapVariables(staticVars, events, file);
  const dropOrder = buildDropOrder(events);
  const result: MergedVariable[] = [];

  // Process mapped variables (have runtime data)
  for (const m of mapped) {
    const runtimeInfo = buildRuntimeInfo(m, events, dropOrder);
    const divergences = detectDivergences(m.static_match, runtimeInfo);
    const agreement = computeAgreement(m.static_match, runtimeInfo, divergences);

    result.push({
      name: m.var_name, var_id: m.var_id,
      line: m.location?.line ?? m.static_match?.line ?? 0,
      file: m.location?.file ?? file ?? null,
      static_info: m.static_match ? {
        type_display: m.static_match.type_display,
        ownership_category: m.static_match.ownership_category,
        is_copy: m.static_match.is_copy ?? false,
      } : null,
      runtime_info: runtimeInfo,
      agreement, divergences,
    });
  }

  // Add static-only variables (no runtime match)
  for (const sv of staticVars) {
    if (!alreadyMapped(sv, mapped)) {
      result.push({ name: sv.name, var_id: null, line: sv.line,
        static_info: { type_display: sv.type_display, ... },
        runtime_info: null, agreement: "static_only", divergences: [] });
    }
  }

  return result;
}

5.2 RuntimeInfo Aggregation from Event Streams

For each mapped variable, the buildRuntimeInfo() function iterates the variable's events and aggregates them into a single RuntimeInfo structure. The aggregation is a single-pass O(n) scan over the events, accumulating counters and tracking state transitions. Each event type contributes to specific fields: creation events set the start timestamp and initial ref counts, borrow events increment counters, move events set the moved flag, drop events set the end timestamp, and clone events track ref count peaks.

The resulting RuntimeInfo contains 14 fields capturing every observable aspect of the variable's runtime behavior: actual lifetime in nanoseconds (drop timestamp minus creation timestamp, or -1 if never dropped), shared and mutable borrow counts, whether it was actually moved and where, its position in the global drop sequence, peak and final reference counts (for Rc/Arc), total clone count, weak reference count peak, number of await crossings, unsafe access count, and total event count. This comprehensive snapshot enables the divergence detectors to compare observed behavior against static predictions across multiple dimensions. 

function buildRuntimeInfo(mapped: MappedVariable, allEvents: RuntimeEvent[], dropOrder: Map<string, number>): RuntimeInfo {
  let createTimestamp = 0, dropTimestamp = -1;
  let borrowCount = 0, mutBorrowCount = 0;
  let wasMoved = false, moveDest: string | null = null;
  let refCountPeak = 0, refCountFinal = 0, weakCountPeak = 0;
  let cloneCount = 0, unsafeAccesses = 0;

  for (const event of mapped.events) {
    const type = eventType(event);
    const data = eventData(event);

    switch (type) {
      case "New": case "RcNew": case "ArcNew":
        createTimestamp = data.timestamp;
        refCountPeak = Math.max(refCountPeak, data.strong_count || 1);
        refCountFinal = data.strong_count || 1;
        break;
      case "Drop":
        dropTimestamp = data.timestamp; break;
      case "Borrow":
        borrowCount++; if (data.mutable) mutBorrowCount++; break;
      case "Move":
        if (data.from_id === mapped.var_id) { wasMoved = true; moveDest = data.to_name; }
        break;
      case "RcClone": case "ArcClone":
        cloneCount++;
        refCountPeak = Math.max(refCountPeak, data.strong_count);
        refCountFinal = data.strong_count;
        break;
      case "RawPtrDeref": case "UnsafeBlockEnter":
        unsafeAccesses++; break;
    }
  }

  const awaitCrossings = detectAwaitCrossings(mapped.var_id, allEvents);

  return {
    actual_lifetime_ns: dropTimestamp >= 0 ? dropTimestamp - createTimestamp : -1,
    actual_borrow_count: borrowCount, actual_mut_borrow_count: mutBorrowCount,
    was_actually_moved: wasMoved, move_destination: moveDest,
    drop_order: dropOrder.get(mapped.var_id) ?? -1, drop_timestamp: dropTimestamp,
    ref_count_peak: refCountPeak, ref_count_final: refCountFinal,
    weak_count_peak: weakCountPeak, clone_count: cloneCount,
    thread_id: null, await_crossings: awaitCrossings,
    unsafe_accesses: unsafeAccesses, event_count: mapped.events.length,
  };
}

5.3 Drop Order Computation

The global drop order is computed by scanning all Drop events in the entire event stream (not just one variable's events) in timestamp order. Each variable that is dropped receives a sequential position number starting from 0. The first variable dropped gets position 0, the second gets 1, and so on. This produces a Map<string, number> from variable ID to drop position.

The drop order reveals the actual destruction sequence, which follows Rust's LIFO (Last In, First Out) rule within a scope but may differ from developer expectations when early drops (std::mem::drop), nested scopes, or conditional destruction are involved. The merge surfaces this information in the Drop Order sub-tab of the Runtime view, showing each variable's position with its lifetime duration. Variables that are never dropped (leaked Rc, mem::forget) do not appear in the drop order map and receive position -1. 

function buildDropOrder(events: RuntimeEvent[]): Map<string, number> {
  const order = new Map<string, number>();
  let idx = 0;
  for (const event of events) {
    if (eventType(event) === "Drop") {
      const data = eventData(event);
      if (data.var_id) {
        order.set(data.var_id, idx++);
      }
    }
  }
  return order;
}

5.4 Agreement Classification (match, diverge, runtime_only, static_only)

After building the RuntimeInfo and running divergence detection, each MergedVariable receives an agreement classification. The classification is straightforward: if there is no static_info (variable only seen at runtime), the agreement is "runtime_only". If there is no runtime_info (variable only seen in static analysis), the agreement is "static_only". If divergences were detected (the divergence list is non-empty), the agreement is "diverge". Otherwise, the two sides agree and the classification is "match".

This four-way classification drives the visualization layer. Matched variables are shown with a green indicator (both sides agree, everything is as expected). Divergent variables are shown with yellow (warnings) or red (errors) indicators depending on the highest severity among their divergences. Runtime-only variables are shown with a gray "runtime" badge. Static-only variables are shown with a gray "static" badge. The developer can immediately see which variables need attention by scanning for non-green indicators.

5.5 Merge Summary Statistics

The mergeSummary() function produces aggregate counts across all merged variables: total count, number of matches, number of divergences, number of runtime-only, and number of static-only. These statistics are displayed in the status bar ("Static OK | Runtime: 12 vars, 2 divergences") and used by the extension to make decisions: if the match count is zero and runtime_only is high, the events likely correspond to a different version of the code (stale events file), and the extension shows a warning rather than misleading divergence data. 

export function mergeSummary(merged: MergedVariable[]): {
  total: number; match: number; diverge: number; runtime_only: number; static_only: number;
} {
  const s = { total: merged.length, match: 0, diverge: 0, runtime_only: 0, static_only: 0 };
  for (const m of merged) {
    s[m.agreement]++;
  }
  return s;
}
