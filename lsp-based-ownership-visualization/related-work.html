2. Related Work

Several tools have attempted to make Rust's ownership system more visible to developers. Each addresses a subset of the problem but leaves significant gaps that motivated the design of borrowscope-lsp.

2.1 Aquascope (Brown University)

Aquascope visualizes permissions (read, write, own) on a per-statement basis, showing how permissions flow through a function body. It operates on MIR (Mid-level Intermediate Representation) and generates static diagrams that annotate each line with the permissions held by each variable at that point. The tool is pedagogically effective for teaching ownership concepts and has been integrated into the official Rust Book's interactive edition.

Limitations relevant to our work: Aquascope operates in batch mode (the developer submits code and receives a rendered image), provides no editor integration, does not track borrows across function boundaries, and does not visualize memory layout. It focuses on permissions rather than structural relationships (who borrows from whom, where moves happen, which Rc clones share ownership).

2.2 RustViz (University of Michigan)

RustViz generates SVG timeline diagrams showing ownership events (creation, borrow, move, drop) along a time axis. The output is visually clear and suitable for educational materials. However, RustViz requires manual annotation: the developer must insert special comments in the source code to mark which variables and events to visualize. This manual effort makes it impractical for day-to-day development and limits its use to prepared examples.

In contrast, borrowscope-lsp requires no source code modification. Analysis is fully automatic, driven by the semantic database.

2.3 Flowistry (Stanford)

Flowistry tracks information flow in Rust programs: given an output, it identifies which inputs influenced it. Built on MIR analysis, it provides a VS Code extension that highlights relevant code slices. Flowistry answers the question "what affects this value?" rather than "who owns this value?" or "which borrows are active here?"

While information flow and ownership are related concepts, they serve different purposes. A developer debugging a borrow checker error needs to see borrow scopes and conflicts, not data dependencies. Flowistry does not provide ownership graphs, borrow scope visualization, conflict detection, or memory layout information.

2.4 REVIS

REVIS (Runtime Execution VISualizer) provides dynamic visualization of Rust program execution, showing how values move through memory during runtime. Like borrowscope-runtime, it requires program execution and traces one path per run. It does not integrate with the editor and provides no static analysis capabilities.

2.5 rust-analyzer Built-in Features

rust-analyzer, the de facto Rust language server, provides type inference, go-to-definition, find-references, inlay hints for types and parameter names, and basic hover information. It uses the same ra_ap_* semantic engine that borrowscope-lsp builds upon. However, rust-analyzer does not provide ownership-specific analysis: no ownership graph, no borrow scope visualization, no conflict detection, no move tracking, no Rc/Arc clone tracking, no cross-function borrow paths, and no memory layout visualization.

borrowscope-lsp is not a replacement for rust-analyzer but a complement. It uses the same underlying database (Salsa + VFS) and the same type resolution APIs, adding an ownership-focused analysis layer on top.
