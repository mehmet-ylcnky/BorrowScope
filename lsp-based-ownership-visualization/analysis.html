4. Ownership Analysis Engine

The analysis engine is the core of borrowscope-lsp. It takes a parsed function AST and the Salsa semantic database as input, and produces a complete FunctionOwnershipSummary containing every ownership relationship in that function. The engine performs 7 distinct analyses in sequence: type extraction, borrow scope computation, move detection, closure capture analysis, Rc/Arc clone tracking, conflict detection, and method call resolution. Each analysis uses only semantic APIs (no string matching on source text, no heuristics based on naming conventions). If the semantic database cannot resolve a type or reference, the analysis skips that item rather than guessing.

4.1 Full Type Extraction (40+ Properties)

For every let binding in a function body, the engine extracts exhaustive type information by calling methods on hir::Type. The result is a VariableOwnershipInfo struct with over 40 fields covering every aspect of the type that is relevant to ownership analysis. This is the same information that the borrowscope-analyzer writes to type-info.json, but computed on-demand from the live Salsa database rather than read from a static file.

The extraction is organized into categories. First, 17 boolean properties that require no database access: is_reference, is_mutable_reference, is_copy, is_closure, is_raw_ptr, is_tuple, is_array, is_fn, is_scalar, and others. Second, properties that require the database: is_copy(db), is_packed(db), contains_reference(db), impls_fnonce(db), impls_iterator(db). Third, decomposition queries: reference inner type, ADT info (struct/enum/union with canonical path), type arguments, future output, iterator item, tuple fields, struct fields, array element type. Fourth, layout information: ty.layout(db) returns size and alignment in bytes. Fifth, drop glue detection via ty.drop_glue(db). 

pub struct VariableOwnershipInfo {
    // Identity
    pub name: String,
    pub type_display: String,
    pub file: String,
    pub line: u32,
    pub column: u32,

    // Boolean type properties (no db needed)
    pub is_reference: bool,
    pub is_mutable_reference: bool,
    pub is_closure: bool,
    pub is_raw_ptr: bool,
    pub is_copy: bool,
    // ... 12 more boolean fields

    // Decomposition
    pub adt_info: Option<AdtInfo>,
    pub struct_fields: Vec<FieldInfo>,
    pub type_arguments: Vec<String>,

    // Layout
    pub layout_size: Option<u64>,
    pub layout_align: Option<u64>,
    pub has_drop_glue: bool,

    // Classification
    pub ownership_category: OwnershipCategory,
    pub trait_impls: TraitImplInfo,
}

4.2 Ownership Classification Algorithm

Every extracted variable is classified into one of 8 ownership categories. The classification uses a priority chain that checks the most specific conditions first and falls through to more general ones. This ordering ensures that a &Rc<T> is classified as SharedRef (not Rc), and that a Copy type behind a raw pointer is classified as RawPointer (not Copy). The algorithm never guesses: if the type is unknown (unresolved generic, inference failure), it returns OwnershipCategory::Unknown.

The ADT path check for smart pointers uses the fully resolved module path from hir::Adt::module().path_to_root(), not the display name. This means use std::rc::Rc as MyRc; let x: MyRc<i32> is correctly classified as Rc because the canonical path resolves to alloc::rc::Rc regardless of the local alias. This is the same semantic resolution that the borrowscope-analyzer uses for type-info.json, ensuring consistency between the static file and the live LSP analysis. 

fn classify_ownership(db: &RootDatabase, ty: &hir::Type, info: &VariableOwnershipInfo) -> OwnershipCategory {
    if info.is_unknown       { return OwnershipCategory::Unknown; }
    if info.is_raw_ptr       { return OwnershipCategory::RawPointer; }
    if info.is_mutable_reference { return OwnershipCategory::MutableRef; }
    if info.is_reference      { return OwnershipCategory::SharedRef; }
    if info.is_copy           { return OwnershipCategory::Copy; }

    // Check ADT canonical path for smart pointers
    if let Some(ref path) = info.adt_canonical_path {
        if path.contains("rc::rc")       { return OwnershipCategory::Rc; }
        if path.contains("sync::arc")    { return OwnershipCategory::Arc; }
        if path.contains("cell::refcell") { return OwnershipCategory::InteriorMut; }
    }
    OwnershipCategory::Owned
}

4.3 Borrow Scope Computation via Definition::usages

For each reference binding in a function (let r = &x or let guard = cell.borrow()), the engine computes the active scope: the range of lines where the borrow is alive. The start is the declaration line. The end is determined by finding the last use of the borrower variable anywhere in the function body. This matches Rust's Non-Lexical Lifetimes (NLL) semantics, where a borrow ends at its last use rather than at the end of the enclosing scope.

Finding the last use is done via Definition::Local(local).usages(sema).all(), which returns every reference to the binding across the file. The engine takes the maximum TextRange::end() among all usages as the borrow's end point. This approach is semantically precise: it accounts for uses inside nested blocks, match arms, and loop bodies. If the variable is never used after declaration (e.g., let _r = &x;), the scope collapses to the declaration line itself.

The engine also recognizes guard types as implicit borrows. When it encounters let guard = cell.borrow(), it checks the return type's ADT path for patterns like cell::Ref, sync::MutexGuard, or sync::RwLockWriteGuard. If matched, the expression is treated as a borrow of the receiver (cell), with mutability determined by the guard type name (e.g., RefMut implies mutable). The target variable is extracted by walking the method call chain backwards through .unwrap() and .expect() calls to find the original receiver.

4.4 Move Detection (4 Patterns)

The engine detects ownership transfers (moves) by identifying four syntactic patterns where a non-Copy, non-reference value is consumed. Each pattern is checked semantically: the engine resolves the type of the moved expression via sema.type_of_expr() and verifies that ty.is_copy(db) is false and ty.is_reference() is false before reporting a move. This eliminates false positives from Copy types like integers or from reference passing.

The four patterns are: (1) assignment move (let b = a where a is a path expression with non-Copy type), (2) function argument move (foo(a) where a is passed by value), (3) return move (return a), and (4) closure capture move (move || { a }, detected via closure_hir.captured_items(db) which returns each captured variable with its CaptureKind). Only path expressions (direct variable references) are considered as move sources; complex expressions like foo(bar()) are not moves because the temporary is consumed in place. 

fn detect_let_move(db, sema, let_stmt, line_index) -> Option<MoveInfo> {
    let init = let_stmt.initializer()?;
    let pat = let_stmt.pat()?;

    // Only path expressions (variable references) can be moves
    let path_expr = match &init {
        ast::Expr::PathExpr(p) => p,
        _ => return None,
    };

    let ty = sema.type_of_expr(&init)?.original;

    // Copy types don't move, references don't move
    if ty.is_copy(db) || ty.is_reference() { return None; }

    Some(MoveInfo {
        source_name: path_expr.syntax().text().to_string(),
        destination: MoveDestination::Variable(pat.syntax().text().to_string()),
        source_type: ty.display(db, display_target).to_string(),
        ..
    })
}

4.5 Closure Capture Analysis via CaptureKind

For each closure expression in a function body, the engine resolves its hir::ClosureId via sema.type_of_expr() and then queries closure_hir.captured_items(db). This returns a list of captured variables, each with a CaptureKind indicating how the variable is captured: SharedRef (closure borrows it immutably), UniqueSharedRef (unique shared access for interior mutability), MutableRef (closure borrows it mutably), or Move (closure takes ownership). The engine also determines which Fn trait the closure implements (Fn, FnMut, or FnOnce) via closure_hir.fn_trait(db).

This analysis is fully semantic. It does not rely on the presence of the move keyword to determine capture mode: even without move, a closure may capture by move if the captured variable is consumed inside the closure body. The compiler determines the minimal capture mode for each variable independently, and the ra_ap_hir API exposes this decision directly. The result is a ClosureCaptureInfo struct listing every captured variable with its mode, type, and the closure's position in the source. 

for capture in closure_hir.captured_items(db) {
    let local = capture.local();
    let name = local.name(db).display_no_db(Edition2021).to_string();
    let capture_mode = match capture.kind() {
        CaptureKind::SharedRef     => CaptureMode::BySharedRef,
        CaptureKind::UniqueSharedRef => CaptureMode::BySharedRef,
        CaptureKind::MutableRef    => CaptureMode::ByMutRef,
        CaptureKind::Move          => CaptureMode::ByMove,
    };
    captures.push(CapturedVariable { name, capture_mode, variable_type: ... });
}

4.6 Rc/Arc Clone Tracking

Shared ownership via Rc and Arc is one of the most important ownership patterns to visualize, because each clone creates a new owner that shares the same heap allocation. The engine detects two clone patterns: method-style (let b = a.clone() where a is Rc<T> or Arc<T>) and explicit-style (let b = Rc::clone(&a)).

For method-style clones, the engine resolves the receiver type via sema.type_of_expr(&receiver) and checks if it is Rc or Arc using the classify_rc_arc function, which inspects the ADT's canonical module path. For explicit-style clones, the engine parses the path segments of the callee (Rc::clone) and checks if the qualifier is "Rc" or "Arc". In both cases, the source variable (the original Rc/Arc being cloned) and the destination variable (the new clone) are recorded with their line positions. This information is used by the visualization to draw shared-ownership edges in the ownership graph.

4.7 Conflict Detection (Overlap Algorithm)

Borrow conflicts occur when two borrows of the same variable have overlapping active scopes and at least one is mutable. The engine detects these by performing an O(n^2) pairwise comparison of all computed borrow scopes. For each pair (a, b), it checks three conditions: (1) both target the same variable (a.target_name == b.target_name), (2) at least one is mutable (a.is_mutable || b.is_mutable), and (3) their line ranges overlap (max(a.start, b.start) <= min(a.end, b.end)).

When a conflict is detected, the engine records the overlap region (the lines where both borrows are simultaneously active), the names of both borrowers, the target variable, and the conflict kind (MutableAndShared or MultipleMutable). These conflicts are surfaced to the editor as LSP diagnostics (informational severity) and as entries in the ownership graph response. The O(n^2) complexity is acceptable because the number of borrow scopes per function is typically small (under 20 in practice).

4.8 Method Call Resolution (Self Borrow Detection)

Every method call in a function body creates an implicit borrow of the receiver. Calling data.len() borrows data as &self; calling data.push(4) borrows it as &mut self; calling data.into_iter() consumes it as self. The engine resolves each method call via sema.resolve_method_call(&method_call) to obtain the hir::Function, then queries func.self_param(db).access(db) to determine the self borrow mode: Access::Shared, Access::Exclusive, or Access::Owned.

Beyond the self borrow mode, the engine extracts the method's canonical path (via module traversal), return type, whether it is a trait method (by checking AssocItem::container(db)), and whether it is unsafe. This information is included in the FunctionOwnershipSummary and can be used by visualization tools to show which method calls create borrows and of what kind. For example, a visualization could highlight all &mut self method calls in red to draw attention to exclusive access points. 

let func = sema.resolve_method_call(&method_call)?;

let self_borrow = match func.self_param(db)?.access(db) {
    hir::Access::Shared    => SelfBorrow::Shared,     // &self
    hir::Access::Exclusive => SelfBorrow::Exclusive,  // &mut self
    hir::Access::Owned     => SelfBorrow::Owned,      // self (consuming)
};

let (is_trait_method, trait_name) = match AssocItem::Function(func).container(db) {
    AssocItemContainer::Trait(t) => (true, Some(t.name(db).to_string())),
    AssocItemContainer::Impl(i)  => (i.trait_(db).is_some(), i.trait_(db).map(..)),
};
